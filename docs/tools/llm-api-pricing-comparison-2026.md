## 一、先弄懂 token：100 万 token 大约是多少字

**大白话解释：** token 是模型读写文本时使用的计量单位，可以理解为模型账单里的“字符片段”，但它不一定等于一个汉字、一个单词或一个字节。

中文大约多少字一个 token，只能写成经验值，因分词器不同而变。对于中文纯文本，100 万 token 换算成汉字，可以先按约 60 万至 150 万汉字做经验估算；代码、英文、数字、网址、JSON 和混合文本的比例越高，这个区间越不可靠。这里的换算只是经验估算，不应替代接口返回的 usage。

最可靠的做法有两种。第一种是实际调用后查看响应里的 usage 字段，分别记录输入 token、输出 token 和缓存 token。第二种是在支持该能力的接口上调用 `/v1/messages/count_tokens`，先对一段准备发送的消息进行计数，再决定是否截断、摘要或分批发送。

- 准备一段真实业务文本，不要只用“你好”测试，因为短文本的分词比例不能代表代码、长文或多轮对话。
- 发送请求并保存返回体中的 usage，同时保存 model、request_id 和时间。
- 把文字长度、token 数和实际费用放在一起比较，形成你自己的平均换算系数。
- 上线后继续以请求日志和控制台调用明细为准，不要用“字符数 × 一个固定比例”长期估算账单。

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ.get("XISU_API_KEY", "sk-xxxx"),
    base_url="https://api.xisu.ai/v1",
)

response = client.chat.completions.create(
    model="gpt-6.1-sol",
    messages=[
        {"role": "user", "content": "请用三句话解释 token 是什么。"}
    ],
    max_tokens=200,
)

print(response.choices[0].message.content)
print(response.usage)
print("prompt_tokens:", response.usage.prompt_tokens)
print("completion_tokens:", response.usage.completion_tokens)
```

如果调用成功，你会看到模型回复和 usage 对象。重点记录 `prompt_tokens`、`completion_tokens`；如果模型或兼容层返回缓存字段，还要记录 `cached_tokens` 或 `prompt_tokens_details.cached_tokens`。

## 二、价格为什么要拆成四部分

**大白话解释：** 一次请求不是只有“输入多少钱”，而是可能同时产生普通输入、缓存读取、缓存写入和输出四类 token 费用。

价格公式可以先记成：

```text
费用 = 普通输入 token × 输入价 + 缓存读取 token × 缓存读价 + 缓存写入 token × 缓存写价 + 输出 token × 输出价
```

再除以 1,000,000，就得到按“每百万 token”报价时的实际金额。不同厂商对缓存的命名和生命周期并不完全相同，因此实际接入时应以对应模型的 usage 字段和官方定价页为准。

| 费用项 | 它代表什么 | 常见影响 |
|---|---|---|
| 输入 | 本次请求中没有从缓存复用的输入 token。 | 系统提示词、用户问题、历史对话、工具定义和文件内容都可能计入。 |
| 输出 | 模型新生成的 token。 | 输出单价通常明显高于输入单价，本文对比表中多数模型约为输入价的 3–6 倍。 |
| 缓存读取 | 本次请求命中已有缓存的输入 token。 | 重复上下文越多、缓存命中越稳定，节省越明显。 |
| 缓存写入 | 首次把可复用上下文写入缓存的 token。 | 首次请求可能比普通输入贵，之后的重复请求才使用缓存读取价。 |

不能只看输入价，主要有三个原因。第一，输出单价通常更高，长回答、代码生成和推理任务会放大输出成本。第二，Agent 会反复携带系统提示、工具说明、代码仓库摘要和历史状态，输入总量远大于普通聊天。第三，Agent 的重复上下文往往适合缓存，此时缓存读取价和缓存写入价会直接决定长期成本。

不同官方 API 的缓存方式也不同。OpenAI 的 Prompt Caching 主要围绕可复用的提示前缀，支持的模型会自动尝试复用相同前缀，并在 usage 中返回缓存 token，缓存部分按更低的单价计费，具体倍率随模型而变。

Anthropic 的 Prompt Caching 通常通过 `cache_control` 标记可缓存内容，并区分基础输入、缓存写入和缓存命中；官方定价页还区分 5 分钟和 1 小时缓存写入，缓存读取通常按照明显低于基础输入的价格计费。

Gemini 提供 implicit caching，也提供适用于部分接口和模型的显式 context caching。官方文档说明，缓存读取会在 usage metadata 中体现；显式缓存还可能涉及缓存 token 数量和存储时间，具体价格和支持范围要按模型页面确认。

以 OpenAI 官方文档为例，提示缓存通常要求请求拥有足够长且稳定的前缀，缓存读取和缓存写入的费率不是统一固定值；以 Gemini 官方文档为例，隐式缓存通常要求相似的前缀在较短时间内重复出现。对于 Anthropic，则需要在消息内容中明确设置缓存控制点。不要把一家厂商的缓存参数直接套到另一家厂商上。

**一次调用的费用 = 普通输入、缓存读取、缓存写入、输出四部分之和。**

## 怎么设计更容易命中缓存的请求

**大白话解释：** 把长期不变的内容放在前面，把每次都变化的问题放在后面。

- 把稳定的系统提示词、角色说明、工具 schema、项目规则和仓库摘要放在前面。
- 把当前用户问题、时间戳、随机数、临时状态和本轮工具结果放在后面。
- 不要因为无关字段变化就重排整个提示词，否则可能破坏前缀匹配。
- 每次调用都保存 usage，确认缓存读写是否真的发生，而不是只凭请求结构猜测。

## 四、四个真实使用场景：100 万 token 到底会花多少钱

**大白话解释：** 同一个模型在不同任务里的成本，取决于输入多少、输出多少，以及重复上下文是否命中缓存。

- 普通聊天：一次输入 2,000 token，输出 500 token，无缓存。

## 五、官方 API、订阅制和第三方 API，怎么选

**大白话解释：** 订阅制买的是某个产品里的使用额度或功能，官方 API 按接口用量计费，第三方 API 通常把多个模型放到统一入口，适合希望少改代码、集中充值和统一核对的人。

| 方式 | 怎么收费 | 适合谁 | 能否用于自己的程序或编码工具 | 通常需要什么支付方式 |
|---|---|---|---|---|
| 官方 API | 按模型、输入输出 token、缓存、批处理或服务档位计费，具体以厂商官方定价页为准。 | 需要直接使用官方控制面、官方能力或企业级 API 管理的团队。 | 可以，通常需要申请官方 API 账号、密钥和支付配置。 | 以对应厂商支持的信用卡、账单账户、预付费或企业结算方式为准。 |
| 订阅制 | 按月或按年支付，通常附带消息量、模型、工具或编码产品的使用限制。 | 主要在网页、桌面端、移动端或官方编码产品中使用的个人用户。 | 一般不能直接等同于 API 余额；例如 Anthropic 明确说明 Claude Pro 不包含 Console API 用量，OpenAI 也明确说明 ChatGPT Plus 与 API 用量分开计费。 | 以产品页面和所在地区支持的支付方式为准。 |
| 第三方 API | 可能按实际 token 用量、模型单价、缓存分项和账户余额结算。 | 需要统一 base_url、同时测试多个模型，或希望使用本地支付方式的个人开发者。 | 通常可以，前提是客户端支持兼容协议或允许自定义 base_url。 | 以平台实际支持方式为准；本站支持支付宝和微信。 |

订阅价格会随地区、产品档位和时间变化，本文不列具体数字，购买前请以 ChatGPT、Claude、Google AI 各自官方页面为准。需要记住的只有一点：订阅额度和 API 用量是两套账，订阅不能当作 API 余额使用。

如果你选择第三方 API，建议至少核对下面六点：

- 是否按 token 实际计费，而不是按“调用次数”粗略扣费。
- 输入、输出、缓存读取和缓存写入是否分开显示。
- 计费精度是否足够高，低单价模型是否会因四舍五入造成误差。
- 请求日志能否通过 request_id 逐笔核对。
- 余额是否过期，失败请求、流式中断和无输出请求如何计费。
- 是否能验证实际调到的是真模型，而不是只看客户端里填写的模型名称。可参考如何确认调用到的是真模型。

本站计费口径是按实际用量计费，精度到小数点后 10 位；积分不过期，¥1 = 100,000 积分，最低充值 ¥10，支持支付宝和微信，调用后结算不预扣。失败请求不计费；流式响应中途断开时，已经生成的部分照常计费。

## 六、成本计算器：把 usage 直接换算成金额

**成本计算公式与 claude-sonnet-5-5 代码助手一轮的算例**

**大白话解释：** 成本计算器不负责猜 token，它只负责把你已经拿到的 token 分项和单价代入公式。

```text
费用 = (普通输入×输入价 + 缓存读取×缓存读价 + 缓存写入×缓存写价 + 输出×输出价) ÷ 1,000,000
```

下面的 Python 函数内置 4 个模型的单价，单位是“元 / 每百万 token”。你可以把价格替换成价格表中的实时数值。

```python
PRICES = {
    "gpt-6.1-sol": {"input": 1.44, "output": 7.20, "cache_read": 0.072, "cache_write": 1.80},
    "gpt-6-luna": {"input": 0.072, "output": 0.36, "cache_read": 0.0072, "cache_write": 0.09},
    "gemini-3.8-flash-high": {"input": 0.54, "output": 2.70, "cache_read": 0.054, "cache_write": 0.54},
    "claude-sonnet-5-5": {"input": 4.32, "output": 21.60, "cache_read": 0.216, "cache_write": 5.40},
}

def estimate_cost(model, normal_input, cache_read, cache_write, output):
    p = PRICES[model]
    total = (
        normal_input * p["input"]
        + cache_read * p["cache_read"]
        + cache_write * p["cache_write"]
        + output * p["output"]
    ) / 1_000_000
    return round(total, 10)

print(estimate_cost("gpt-6.1-sol", 2000, 0, 0, 500))
print(estimate_cost("claude-sonnet-5-5", 70000, 500000, 30000, 30000))
```

第一行会得到约 0.0065 元，第二行会得到约 1.2204 元。若结果与表格有极小差异，通常是显示位数或四舍五入造成的。

```javascript
  "claude-sonnet-5-5": { input: 4.32, output: 21.60, cacheRead: 0.216, cacheWrite: 5.40 }
};

function estimateCost(model, normalInput, cacheRead, cacheWrite, output) {
  const p = prices[model];
  const total = (
    normalInput * p.input +
    cacheRead * p.cacheRead +
    cacheWrite * p.cacheWrite +
    output * p.output
  ) / 1000000;
  return Number(total.toFixed(10));
}

console.log(estimateCost("gpt-6.1-sol", 2000, 0, 0, 500));
console.log(estimateCost("claude-sonnet-5-5", 70000, 500000, 30000, 30000));
```

浏览器控制台会输出两个数字，分别对应普通聊天和带缓存的 Agent 任务。实际项目中可以把 prices 替换成后端配置，避免价格变化时重新发布前端代码。

## 七、六条可执行的省钱建议

**大白话解释：** 省钱不是单纯换成低价模型，而是减少不必要的 token、让重复内容命中缓存，并让每一轮 Agent 都有明确边界。

- **简单任务选小模型。** 分类、改写、提取字段、格式转换和短问答可以先用低价模型；只有在准确性、复杂推理或代码质量不够时，再切换更高档模型。
- **控制 `max_tokens`。** `max_tokens` 不是一定会全部扣费，但它会给模型更大的输出空间。对固定格式的任务，设置合理上限并要求简洁输出，通常更容易控制账单。注意：本站 GPT 系列目前 `max_tokens` 这类输出上限参数没有生效，输出可能超过上限并按实际输出计费（见低价 API 中转怎么辨别第 7 节）；修复前，GPT 模型请先在提示词里要求简短输出。Claude 系列正常。
- **固定系统提示词前缀。** 把角色、规则、工具 schema 和项目约束放在固定前缀，动态问题放在后面，有助于提高缓存命中机会。OpenAI 官方文档强调稳定的 prompt prefix，Gemini 官方文档也建议把大段公共内容放在前面并在较短时间内重复使用。
- **长文先摘要。** 不要在每一轮都把完整文档、全部历史对话和所有工具结果重新发送。可以先生成结构化摘要，再让后续请求携带摘要和当前相关片段。
- **限制 Agent 轮数。** 给任务设置最大轮数、最大总 token、最大工具调用数和超时。一个“直到完成为止”的循环，很容易把输入和输出成本同时放大。
- **按 request_id 核对账单。** 每天或每周抽样对比响应 usage、客户端日志和控制台调用明细。遇到余额差额时，带上时间范围、模型、request_id 和完整错误响应体，而不是只说“账单不对”。

## 八、从价格表到第一次调用的操作清单

如果你是第一次接 API，可以按下面顺序操作：

- 先明确任务类型：普通聊天、长文总结、代码助手还是多轮 Agent。
- 记录一次真实请求的输入长度、预期输出长度、是否会重复发送相同上下文。
- 到模型价格表查看输入、输出、缓存读写价格，并确认页面显示的当前可调用状态。
- 用本文公式或成本计算器计算单次费用，再乘以每天调用次数和每月天数。
- 注册后充值，本站最低充值 ¥10，积分不过期，支持支付宝和微信。
- 到控制台创建密钥。密钥明文只显示一次，创建时立即保存到密码管理器或环境变量中。
- 把客户端的 `base_url` 指向 `https://api.xisu.ai/v1`，使用 `XISU_API_KEY` 环境变量保存密钥。
- 完成第一次调用后，保存 response usage、模型名称和 request_id，再到控制台调用明细核对费用。

如果你的客户端不是 OpenAI SDK，也可以查看 OpenAI 兼容接口说明；如果使用 Anthropic 原生消息格式，可以查看 Anthropic Messages 接入说明。不同端点的返回字段和参数支持范围可能不同，先确认端点，再复制示例。

## 常见问题

### 100 万 token 到底是多少钱？

没有统一答案。输入和输出价格不同，缓存读取和缓存写入价格也不同。按照本文本站价格表，gpt-6-luna 的普通输入每百万 token 为 0.072 元、输出为 0.36 元，而 claude-opus-5-5 的普通输入为 8.64 元、输出为 43.20 元。真实费用还要看你的输入输出比例和缓存命中情况。

### 中文 100 万 token 是不是 100 万个汉字？

不是。中文大约多少字一个 token，只能写成经验值，因分词器不同而变。可以先把 100 万 token 粗略估成约 60 万至 150 万汉字，但代码、数字、英文、JSON 和混合文本会明显改变结果。最可靠的方法是查看响应 usage，或调用支持的 `/v1/messages/count_tokens` 计数接口。

### 为什么输出价通常比输入价高？

输出是模型逐步生成的新 token，很多模型的输出单价高于输入单价。本文价格表中的多数模型，输出单价约为输入单价的 3–6 倍，所以长回答、代码生成、推理结果和 Agent 的最终输出都需要单独估算。

### 缓存读取和缓存写入有什么区别？

缓存写入是第一次把可复用上下文放进缓存，缓存读取是后续请求复用已经存在的上下文。写入可能比普通输入贵，读取通常更低价，但缓存生命周期、最小 token 数、匹配规则和 usage 字段由各厂商和模型决定。

### ChatGPT Plus 或 Claude Pro 能直接抵扣 API 费用吗？

通常不能直接这样理解。OpenAI 官方帮助页说明 ChatGPT Plus 的订阅与 API 用量分开；Anthropic 官方帮助页也说明 Claude Pro 不包含 Console API 用量。订阅主要用于对应产品里的功能和额度，自己的程序通常需要单独配置 API 账号与计费。

### 第三方 API 会不会按月固定收费？

本站按实际用量计费，没有月租和最低消费，但需要先充值余额；调用结束才结算，不预扣。失败请求不计费，流式中断时已经生成的部分照常计费。具体账单以控制台调用明细和页面上的数据截至时间为准。

### 为什么响应里只有 prompt_tokens，没有 cached_tokens？

不同模型、端点和兼容层返回字段可能不同。先查看完整 JSON，再查看控制台调用明细中的输入、输出和缓存读取分项。如果页面显示“—”，它表示没有拿到这个数，不等于真实数值为 0；对账时可以通过 request_id 提交工单。

### 怎么确认调用到的是真模型？

不要只看客户端填写的 model 字符串。可以按照模型验证教程发送指定测试请求，结合返回的模型信息、特征输出和控制台日志交叉确认。模型名称、别名和当前可调用状态都可能变化，最终以实时页面和实际响应为准。

### 生图模型也按 token 计费吗？

本文提到的 gpt-image-2.5 系列按张计费，每张 4,500 积分，约 ¥0.045。图片尺寸、质量、模型版本和页面规则可能变化，使用前应查看价格表的当前说明。

### 密钥可以直接写进前端 JavaScript 吗？

不建议。浏览器代码、移动端安装包和公开仓库都可能暴露密钥。开发环境使用 XISU_API_KEY 环境变量，生产环境把请求放在自己的后端，并限制密钥权限、定期轮换和检查请求日志。可以参考密钥安全说明。
